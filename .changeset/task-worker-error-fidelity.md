任务子系统通信优化（隔离 worker ↔ 主线程）：**错误保真**——worker 内 run 抛错改为按 `{ name, message, stack, props }` 序列化回传（`props` 收集自定义可枚举属性，如业务错误类的 `code`/`statusCode`），宿主侧重建 `Error` 并回填，`record.error` / `onFailed` 钩子不再只剩 message。注意：class 身份不跨线程（重建对象是 `Error` 实例），`instanceof 自定义 Error 子类` 在宿主侧不成立，跨线程判错请用 `err.name` / 自定义属性；`props` 含不可克隆值时丢弃 props 保底 name/message/stack（已记入 `fallback.md`）。**任务进度上报**——`TaskContext` 新增可选 `progress(value)`：执行中主动上报进度并记入 `TaskJob.progress`（`list()` 可见），进程内直写记录、隔离路径经消息回传，值必须可结构化克隆；仅 running 状态生效，派发清空上一轮。**快速失败**——`externalSignal` 派发时已 aborted 时不创建 worker 直接失败，不空等宽限期。**取消宽限期可配置**——任务 meta 新增 `graceMs`（毫秒，仅声明 `timeoutMs` 的隔离任务生效）：两段式取消发出 abort 信号后等待任务自行退出的时长，默认 5s，收尾耗时长的事务型任务可调大、无需收尾的任务可设 `0` 判定取消即硬杀。**timeoutMs 最小值 60s**——声明超时的语义是"这是需要真取消的长任务"，一分钟内能跑完的任务没必要声明超时（去掉 `timeoutMs` 走进程内执行即可，需要 deadline 自行用 `Promise.race` 实现）；且超时从派发起算、包含 worker 冷启动（线程创建 + 模块加载），过小的超时会在任务做任何事之前就被取消。低于阈值在扫描期（dev/build 启动时）显式报错不钳制。顺带修复：任务 meta 数字字面量的下划线分隔符（如 `60_000`）此前被正则截断成 `60` 的静默错值，现已正确解析。**内存护栏**——任务终态记录（done/failed/cancelled）设 1000 条上限，超限按最旧优先淘汰（pending/running/retry 永不淘汰）；`list()` 为进程内观测快照而非持久化历史，更早记录由驱动侧 `listQueued` 视图承担。worker 消息反序列化失败（`messageerror`）按执行错误终局。新增宿主 `createTaskRegistriesView` 与 worker 重建视图的输出一致性对照测试，锚定两份实现防语义漂移。
